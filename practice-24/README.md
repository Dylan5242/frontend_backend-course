# Практические занятия 19-23

В рамках практических занятий были выполнены задания по серверной разработке, работе с базами данных, кешированию, балансировке нагрузки и контейнеризации приложений.

## Практическое занятие 19. PostgreSQL

Реализовано серверное API для управления пользователями на Node.js и Express с подключением к PostgreSQL. Для сущности пользователя используются поля `id`, `first_name`, `last_name`, `age`, `created_at`, `updated_at`.

Выполнены основные CRUD-операции:

- `POST /api/users` - создание пользователя;
- `GET /api/users` - получение списка пользователей;
- `GET /api/users/:id` - получение пользователя по идентификатору;
- `PATCH /api/users/:id` - обновление данных пользователя;
- `DELETE /api/users/:id` - удаление пользователя.

Логика маршрутов связана с базой данных PostgreSQL, запросы выполняются через SQL, ответы возвращаются в формате JSON.

## Практическое занятие 20. MongoDB

Реализовано API для управления списком пользователей с использованием NoSQL-базы данных MongoDB. Подготовлена структура документа пользователя с полями `id`, `first_name`, `last_name`, `age`, `created_at`, `updated_at`.

Выполнены маршруты для создания, чтения, обновления и удаления пользователей. Логика каждого эндпоинта связана с MongoDB, также рассмотрены индексы для ускорения поиска и агрегирующие запросы для обработки данных.

## Практическое занятие 21. Redis

Доработано серверное приложение с JWT-аутентификацией, ролями пользователей и кешированием через Redis. Реализована регистрация и авторизация пользователей, выдача access- и refresh-токенов, middleware для проверки авторизации и прав доступа.

Добавлено кеширование GET-запросов:

- `GET /api/users` - кеш на 1 минуту;
- `GET /api/users/:id` - кеш на 1 минуту;
- `GET /api/products` - кеш на 10 минут;
- `GET /api/products/:id` - кеш на 10 минут.

Для товаров реализованы операции создания, обновления и удаления, а также очистка устаревшего кеша после изменения данных.

## Практическое занятие 22. Балансировка нагрузки

Реализована тестовая система балансировки нагрузки для веб-приложения. Подготовлены несколько backend-серверов, работающих на разных портах, и настроен Nginx как балансировщик нагрузки.

Выполнены:

- распределение входящих запросов между backend-серверами;
- проверка повторных запросов через балансировщик;
- настройка отказоустойчивости через параметры health check;
- альтернативный пример балансировки через HAProxy.

Балансировка позволяет распределять трафик между экземплярами приложения и продолжать обработку запросов при недоступности одного из серверов.

## Практическое занятие 23. Docker

Реализовано контейнеризированное веб-приложение с несколькими backend-сервисами и балансировкой нагрузки через Nginx. Работа выполнена в среде WSL с использованием Docker и Docker Compose.

Подготовлены:

- backend-сервисы на Node.js и Express;
- `Dockerfile` для сборки backend-контейнера;
- конфигурация Nginx для балансировки;
- `docker-compose.yml` для запуска всех сервисов в одной сети;
- проверка распределения запросов между контейнерами;
- проверка отказоустойчивости при остановке одного backend-контейнера.

Система запускается одной командой через Docker Compose, после чего Nginx направляет запросы на доступные backend-контейнеры.
